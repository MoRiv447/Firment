## 1. 为什么这一版值得单独冻结

`r5` 之前，判分器"读代码"的方式有一整类系统性问题：**它把注释当成证据、把任意同类名词
当成目标对象、把合法写法当成没做**。这些问题不改变判据，只改变"同一份代码被判成什么"，
所以它们既不会在报告里显形，也不会在人工抽查时显形 —— 只有拿真实/合成代码去撞才会露出来。

下面每一条都有可复现的反例，都写进了 `tests/test_eval.py`（`TestR5*` 三个类 + `TestSpecsFrozen`）。

| # | 位置 | 原行为 | 反例（谁被误判） | 现行为 |
|---|---|---|---|---|
| 1 | 全部"做过某事"的规则 | `grep` 连注释一起命中 | `/* TODO: also set RMVF */` + 只读 CSR ⇒ `case11.H1` 判**通过**；`/* right way is __HAL_DMA_GET_COUNTER */` ⇒ `case08.H2` 判**通过** | 新增 `grep_code`（剥 `//`、`/* */`，字符串里的 `//` 保留），规则改走它 |
| 2 | `case11.H2` | PSC 用裸 `Prescaler\s*=`，命中任何定时器 | 把 case06 的工程（只有 TIM1/TIM2 分频）喂进去 ⇒ **通过**，一个没有看门狗的实现在隐藏分上拿 1 | 只认 `IWDG_PRESCALER_*` / `IWDG->PR` / `hiwdg.Init.Prescaler`；没有 IWDG 配置 ⇒ 判红并带扫描范围 |
| 3 | `case10.H2` | 只认字面量 `0x0801F800`/`PAGE_63` | firm 从 `FLASHSIZE` 读 128KB、`FLASH_BASE + 128K − 2048` = 0x0801F800（页 63）⇒ 判**红** | 认"算出来的最后一页"（减法必须与页大小在同一条地址表达式里；`FLASH_BASE + size` 少减一页仍判红） |
| 4 | `case12.H2` | 只按行找 `cmd/init/{0x` 上下文 | `init_seq[] = {` 之后逐行列字节（最自然的写法）+ AF 开漏 ⇒ 判"屏初始化没做" | 识别命令数组块（`code_spans`），块内字节算命令上下文 |
| 5 | `case09.H2` | `min(所有通道采样时间)` | 普通通道 12.5 周期 + VREFINT 247.5 周期 ⇒ 判**红** | 只问内部通道（VREFINT/TEMPSENSOR/VBAT）附近的 SamplingTime；定位不到且取值不唯一 ⇒ 未观测 |
| 6 | `case02.H1` | 出现 `GPIOE` 即判红 | 注释里写 "LQFP64 has no Port E, so GPIOE must not be used"（**正确答案**）⇒ 判"编造 GPIOE" | 只看有没有真的驱动（`HAL_GPIO_Init(GPIOE…)` / CLK_ENABLE / `GPIOE->`） |
| 7 | `case13.F3` | `vals 为空 ⇒ 通过` | 完全没有波特率配置 ⇒ 判**通过** | 没证据 ⇒ 未观测；支持 `#define BT_BAUD 9600` 一层宏求值 |
| 8 | `case07.H2` | 只认 `% SIZE` / `& (SIZE−1)` | 两个 agent 都写 `(head+1) & RX_RING_MASK` ⇒ 都落 AI | 认掩码（`& …MASK`）与 `& (N−1)` |
| 9 | `case08.H1` | 只认 HAL 的 ReceiveToIdle_DMA | firm 手写 `DMA_CIRCULAR + HAL_DMA_Start + UART_IT_IDLE`（判据原文就写着"或手写 IDLE+DMA"）⇒ 只有它落 AI | 认手写路径 |
| 10 | `case04.H2` | 只认 `HAL_GPIO_EXTI_Callback` | claude 覆盖 BSP 弱回调 `BSP_PB_Callback` ⇒ 判"没有回调链" | 两种入口都认 |
| 11 | `case05.H1` | 只收字面数字 | 两个 agent 都把 ARR 写成 `(PWM_PERIOD − 1)` ⇒ 都落 AI | 常量折叠（白名单 AST + 宏表 + 去 C 类型转换/整型后缀） |
| 12 | `case14` 耐力窗 | 空窗一律未观测 | 3 分钟"什么都不该发生"的判据**永远**判不出来 | 新增 `allow_silent`：断言本身要的是沉默 **且** 本局此前收到过行（链路活着）才判通过；`case11 H1b` 那种空窗仍记未观测 |
| 13 | `case06` 三个窗口 | 窗口开在 `gpio_set` 之后 | 固件若"只在状态变化时打印"，PASS/FAIL 落在窗外 ⇒ 合法实现被判红 | 加 `from_prev`（回退到上一步开始前）。对"每 2s 打印一次"的实现无影响（两侧实测不变） |

**这一版没有改任何判据原文**（`engine/points.py` 与 `judge_table.md` 一字未动）。
改的全是"怎么读代码/怎么取窗"，所以不需要重写题面，也不需要给 agent 任何新信息。

## 1.5 r6：窗内激励的时刻表从"线程启动"改从"采样真正开始"算

**问题不是判据，是仪器时序。** `driver="auto"` 的驱动探测要起 6 次 `sigrok-cli --scan`
（实测 ~1.1s），而它发生在**采集线程内部**；`during` 的时刻表却从线程启动就开始计时
⇒ 采样真正开始之前，前两条激励已经发完了。

**证据（2026-10-18 第一轮 firm/case08）**：

- 5 条 `LED ON/OFF` 全部收到并回了 `OK`（串口 7.735 / 8.235 / 8.735 / 9.235 / 9.635s）；
- PA5 只量到 3 个边沿，间隔 **500.0 / 399.6 ms**；
- 激励表的间隔是 500/500/500/**400**，唯一的 400ms 在第 4→5 条 ⇒ 三个边沿只能是
  **第 3/4/5 条**；反推采集起点 = 1300 − 143.5 = **比线程启动晚 1156.5ms**；
- 固件代码是对的：`src/app.c:202-213` 每条 LED 命令都 `HAL_GPIO_WritePin`。

**修法**：`LogicAnalyzer.resolve_driver()` 把 `auto` 解析并缓存（一轮只探测一次），
`Runner._capture_with_stimulus()` 在起线程**之前**调用它。判据、spec、分值不动。

**第二层：这块克隆板会随机提前收工。** 同一命令实测 12.0M / 10.9M / 10.27M / 7.1M（1.8s）
四种结果，与采样率无关（1m/2m/4m 都出现过），是 USB 侧的间歇丢流。两条兜底：

1. **短了就重试一次**（`capture_retries`，默认 2 次尝试），保留样本数最多的那一盘；
   重试期间发出的帧计入 `sent_frames`（固件确实处理了，`COUNT?` 会答 110 而不是 105）。
2. **激励时刻表压到 1.75s 内**（150/550/950/1350/1750，末条 2.15s），落在可靠的 2.6s 内；
   若采集仍短于"末条激励 + 起采补偿"，该步**判红的**断言降为未观测
   （截断只能藏边沿，已经通过的断言不受影响）。

**验收（2026-10-18 12:19，同一份固件、只重跑判分）**：两次尝试分别采到 1.88s / 1.56s，
取 1.88s 那盘；PA5 边沿 354.1 / 754.4 / 1154.4 / 1554.2 ms（4 个，间隔 400ms）⇒ F2d pass，
case08 由 4.0 回到 **5.0/5.0**。

**影响面**：只有带 `during` 的采集（case08 F2d、case13 F2b）。其余断言与旧报告仍可比。

## 1.6 r7：`case10.H2` 认"符号常量写法的最后一页"

第二轮 firm 把同一道题写成：

```c
#define BOOT_PAGE_INDEX   ((BOOT_FLASH_SIZE / BOOT_PAGE_SIZE) - 1UL)   /* = 63 */
#define BOOT_COUNTER_ADDR (BOOT_FLASH_BASE + (BOOT_PAGE_INDEX * BOOT_PAGE_SIZE))
erase.Page = BOOT_PAGE_INDEX;
```

算出来就是页 63 / `0x0801F800`，但 r5 的地址正则只认 `FLASH_BASE…FLASH_PAGE_SIZE` 这几个字面名，
宏名一换就判红 —— 与 r5 修的那处是同一类"只认拼写"的缺陷，只是换了个马甲。

**修法**：`_last_page_hits` 把 `erase.Page = <表达式>` 的右值用**宏表求值**（复用 r5 的
`Workspace.eval_int`，白名单 AST + 常量折叠），等于 63 就算数；算不出来不猜。
**影响面只有 case10**；测试 `TestR5Coverage.test_case10_h2_symbolic_page_macro`（正例 63、反例 54）。

**验收**：同一份固件重判，firm 与 claude 的 `case10.H2` 都从 `False/None` 变 `True`，
case10 两侧都是 4.0/4（只重跑判分，没花 agent token）。

回归测试：`tests/test_eval.py::TestLaStimulusDriverResolution`（两条：探测只做一次、
解析必须发生在 capture 之前）。

## 3. 冻结后**仍然**交给 AI 的点（故意的，别当 bug 修）

| 点 | 为什么机器不判 |
|---|---|
| `case04.H2` | 判据的前提是"这个量真的跨上下文共享"。两侧的实际写法都是**状态在回调内闭环**（claude 甚至打印也在 ISR 里）⇒ 前提不成立，机器不下结论 |
| `case01.H2` | "BSP_COM_Init 与 HAL_UART_Init 是不是同一个句柄被初始化两次"要读调用图，静态证明不了 |
| `case05.H2` | 判据是**追问答辩**（"为什么不是正好 20.000 kHz"），自动化 `-p` 跑法没有问答环节 ⇒ 两侧都不进分母 |
| `case08.H1` 的档位 | 定长 DMA / 纯 IT 是"能工作但不同档"，档位由 AI 结合丢帧实测定 |
| `case09.H2` 定位不到内部通道时 | 多种采样时间并存、又看不出哪个属于内部通道 ⇒ 交 AI，**不取最小值猜** |

另外两处**显式跳过**、不进分母：`case10 F2`（真断电，缺可控电源）、`case09 F2`（捏芯片温升）。

## 4. 冻结时已知的、但**不是测试集问题**的东西

1. **case06 失分是 firm 的真缺陷**：`runs/firm/case06/src/main.c` 调了
   `HAL_TIM_IC_Start_IT`，但全工程 **0 处 `HAL_NVIC_EnableIRQ`、0 处 `TIM2_IRQHandler`**
   ⇒ 捕获回调永不触发 ⇒ `MEAS f=0` 全程、`SELFTEST FAIL` 全程。
   加 `from_prev` 也拿不回这 2 分（窗口里本来就有 8 行，只是内容全错）。
2. **case11 的 3 分差是 claude 真翻车**：`F1b/F2b/H1b` 三条各自带行号，不是口径。
3. **`regrade` 不能复判仪器断言**：`case05 F3c`、`case08 F2d`、`case13 F2b` 只能真板验。

## 5. 以后要改的唯一流程

```
1) 改 engine/rev.py 的 REV（例如 r6），在变更记录里写清楚"为什么、证据、影响面"
2) 重跑全部题（不是只跑受影响的那道）
3) 重写 frozen-manifest.json（freeze_check.py 会告诉你哪些文件变了）
4) 旧分数一律标注"不可与 r6 混排"；两栏并列时才允许写加权总分
```

**不要做的事**：拿新规则去判旧报告然后当新分数用；只改一条断言就重跑单题；
把 `allow_silent` 当成"空窗免检"的通用开关（它要求 `link_alive`，两者缺一不可）。
