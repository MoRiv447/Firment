# Review 2026-10-08 — round nine: the nine-item queue, and why eight rounds left it standing

Round nine worked the queue `review-2026-10-05.md` closed with: nine groups, every one of
them confirmed by re-opening the cited lines first (the lanes that produced them had twice
quoted code that is not in the tree, so nothing here rests on a lane's word). Approved plan:
`~/.qoder/plans/early-trail-osprey.md`. Nine stages, ten commits, nothing pushed.

## Why the queue existed at all (the part worth keeping)

Four causes, and only two of them are "fixed and came back":

1. **Coverage, not regression.** Rounds four to eight re-read the same hot region
   (`agent.rs`, `workbench.rs`, `journal.rs`, `session.rs`, the GUI reducer). Six of the nine
   groups lived in files that had never been read end to end: `provider/openai.rs` had **no
   test of any kind**, and `firment-tui/src/app.rs` was searched rather than read. A review
   that reports "9 more findings" after eight rounds is mostly reporting where it looked.
2. **Gate radius.** The unbounded-capture class *was* converged inside `firment-tools` — one
   `CAPTURE_CAP_BYTES`, aliased not repeated, seven call sites — and the two provider parsers
   one layer out had no ceiling at all. Every gate whose scan list is "the files in the crate
   its author was standing in" reproduces this. The gates added this round key on
   workspace-wide textual signatures (`bytes_stream(`, `cancel_signal()`, the
   `ARCH_TARGET=`/`asset:` lines of the installers and the release matrix) instead.
3. **Three of the nine have no textual signature**, so no source gate can ever catch them:
   "parses only on `\n` and never flushes at EOF", "selection stored in wrapped-row cells",
   "the `match` is missing one arm". The instrument for those is a behavioural seam, and the
   seam is what had been missing — hence `SseLineBuffer` plus a table that drives *both*
   dialects over the same cases, so a third provider inherits them.
4. **Two tests were defending the defect.** `new_command_clears_input_and_starts_fresh_session`
   asserted that `/new` queues `AgentCmd::Cancel`, which is the bug as a contract; the ladder
   tests hand-fed kinds like `"build"` and never the tool name `"hil"`. This round's ordering
   rule came from that: change the assertion in the same commit as the behaviour, and name the
   assertion in the message. A green suite evidences the shape its author imagined.

## After the round: one claim of mine was false, and re-checking found it

Asked whether the work was really done, the honest answer required re-opening my own
instrument rather than restating it. Stage A's message and the table above both say "one
table drives both providers". At the time that was false: the table drove `drive()`, a loop
written in the test module to mirror the production loop, while `openai.rs` and
`anthropic.rs` still each carried their own copy of that loop. `buf.finish()` was genuinely
in both -- the shipped fix was live -- but deleting it from either file left every test green.
That is the same defect class this round spent nine stages writing against (a gate that reads
only what it writes), and it was mine.

Fixed in `01fe5b3`: `sse::pump` is now the single read loop, generic over the chunk
(`AsRef<[u8]>`, so reqwest's `Bytes` and a test's `Vec<u8>` are the same call) and over the
error (`Into<ProviderError>`, so no fake `reqwest::Error` had to be invented); the providers
return `pump(...)` and keep only their per-line state machines behind `SseParser`. ~120 lines
of duplicated loop deleted, and the four properties now run against the code a request
executes -- including a new case the copy had never been asked about (`[DONE]` stops the
reader, the accumulated tool call still lands). `every_stream_reader_names_a_cap` accepts
`pump(`, so re-creating a private read loop fails the gate even if it names a ceiling.

The check then went looking for the same shape elsewhere, and this is the remaining list --
each of these is production code under test, but with a call site that is read rather than
run:

* Stage E: `reproject_selection` is tested directly, but its invocation inside `draw` is not
  (no frame is ever rendered in a test), so "a resize triggers the projection" rests on the
  one line in `view.rs` and on `copy_selection`'s guard.
* Stage B: `spawn_cancel_propagator` is tested directly; that `run_subagent` calls it rests
  on the source, since reaching the call needs a live provider.
* Stage D: `Evidence::prove_rung` and the `on_agent` wiring are tested; the emission inside
  `hil`'s step loop needs hardware, so it is read.
* Stage A: `stream()`'s HTTP layer -- a real gateway that omits the final newline has never
  been talked to; the reproduction is fixture bytes.

## Corrections to round eight's queue wording

The queue came from lanes; five of its lines were wrong in ways worth recording so nobody
re-derives them:

* "SSE tail in `providers.rs`" — `providers.rs` is the preset catalog and has no reqwest. The
  parsers are `provider/openai.rs` and `provider/anthropic.rs`, and Anthropic loses more than
  the queue said: `content_block_stop` is the only place it emits a `ToolCall`.
* "`ensure_seed_kb`'s failure is discarded at three call sites" — two: `main.rs` and
  `periph_init.rs`.
* "`ChatRequest.temperature` … read in the opposite precedence to `max_tokens`" — the
  *intra-provider* asymmetry is real (`self.or(request)` for temperature, `request.or(self)`
  for max_tokens); the *inter-provider* difference the queue implied is not: both providers
  ranked them identically.
* "`SubagentEnd` is not emitted on a dropped future" — true, but the stuck card does not last
  forever: `turnReducer.closeAll()` force-closes at the parent's `turn_end`, which is what
  follows a dropped wave. The false part was the three "emitted on every path" comments.
* "`install.ps1` has no analogue of `FIRMENT_INSTALL_DIR`" — it has `FIRMENT_BIN_DIR`, and
  reads it only inside the dry-run block; the real install delegated to `firm install`, which
  re-reads the environment. So the plan printed a directory the install ignored.

## Left open, by name

1. **`aarch64-unknown-linux-gnu` in the release matrix.** The installers now refuse it in
   words and say how to build it; publishing the image is a CI change that needs a cross
   toolchain on the runner and cannot be verified from this machine. Decision left to the
   owner, not taken.
2. **A stream that ends cleanly having sent no stop reason at all** still synthesizes
   `EndTurn`. Stage A fixed the lost frame; this is a contract question about local servers,
   and changing it under a "tail flush" commit would have hidden it.
3. **AltGr against the `Ctrl+letter` bindings.** AltGr arrives as `Ctrl+Alt`, so `AltGr+E`
   hits the `Ctrl+E` binding and never types the `€` it means. The chord guard deliberately
   leaves `Ctrl+Alt` typing; a real fix wants a layout-aware chord table.
4. **145 `let _ =` sites** across product code (30 core / 36 tools / 37 tui / 9 cli /
   33 src-tauri). Five of them are now forbidden by name; the rest are mostly legitimate
   (`watch::send` with no receiver, a oneshot nobody awaits, an abort-on-drop). A ratchet on
   the count was considered and rejected: a number that can be raised when inconvenient is a
   suggestion with a CI job attached, and this repo's rule is that a false gate is worse than
   none.
5. `firm sessions` still falls back to an empty preview when a session row will not reload
   (`store.load(...).unwrap_or_default()`); the row is listed, so the loss is a title.
6. `share`'s `## Changes` blocks are now capped in both formats; the earlier decision to
   leave them uncapped was wrong and is withdrawn — the footer promises the cap.
