读这张页面的正确方式

  • 能做的部分:三样全是纯 CSS,WebView2/Chromium 都原生支持,不需要任何依赖。 backdrop-filter 做玻璃、SVG feTurbulence 做颗粒(内联 data-URI,一次绘制)、 box-shadow 的 inset + 多层做内外发光。
  • 顺序上的判断:② 是地基,③④ 是装修。如果只能选一个,选 ② —— 昨晚那个"会话行选不中"的 bug,根因就是缺少一套真正可用的高度阶梯(浅色里两个表面值相同)。 在平地上加玻璃和发光,得到的是油腻,不是质感。
  • 玻璃的硬限制:它必须有东西可以"糊"。我们大部分面板背后是纯色,那里加玻璃 = 什么都不会发生。 真正有意义的位置只有三处:标题栏、状态栏、以及 rail / 检查器的标题条(内容从下面滚过的地方)。
  • 发光的硬限制:发光只有在状态上才读得出来(聚焦、运行中、出错)。当装饰用会立刻变成"游戏 UI"。 而且我们这套设计里饱和色已经有一个明确含义(控件开着),发光不该去抢它。
  • 关于 Stitch:它出的是静态稿。而这里的难点不是"长什么样",是"这套样子要在 500 多个 CSS module 里、 在两套配色下、在真实内容(diff / 日志 / 表格)上一致地成立"。 如果你去 Stitch 做一版,我建议把它当作目标稿而不是灵感板 —— 我来负责把它落进 token 层并保证两种配色都对。
