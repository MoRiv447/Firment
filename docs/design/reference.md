# 参考与取舍

> 这份文件的唯一作用:让"这里看着不对"这句话**有对象**。
> 每次说某处不对,请指向下面某一条 —— 否则它只是偏好,不是缺陷。
>
> 这不是灵感板。**一屏只拿一条决定**,拿多了就是拼贴,而拼贴谁都认得出来。

## 0. 为什么要有这份文件

`docs/design/tokens.md` 是**材质层**(颜色 / 圆角 / 间距),它写得不错。
缺的是**版式层**:谁多宽、字号阶梯、密度、空态说什么、窄窗口怎么办。

"好不好看"恰恰在版式层决定。没有外部标尺时,内部的数字会自己漂 —— 证据:
token 写 `chip 4 / control 6 / panel 12`,文档写 `徽章 2 / 控件 4 / 卡片 8`,两边对不上,而且**都没有给按钮留那个 8**。角落是症状,漂移才是病。

## 1. 参考对象

| 参考 | 拿哪一层 | 为什么是它 |
|---|---|---|
| **Zed**(开源) | 对话流、工具条目、rail 行的两行式 | 产物完全一样:一个 agent 干活的流,含工具调用与 diff |
| **Linear**(闭源) | 框架、列表密度、agent 面板、活动流、空态 | 公开作品里最自律的一套:层级、密度、明暗对等 |

两者的数字来源不同,这点重要:

- **Zed 是开源的** → 字号/行高/间距**读源码和默认设置**,不用截图。已读到:`buffer_font_size 15px`、`buffer_line_height "comfortable"`、`buffer_font_weight 400`、`agent_font_size null`(**继承 UI 字号**)。`ui_font_size` 待从其仓库默认设置读。
- **Linear 是闭源的** → 数字只能从**运行版 devtools** 抄(见 §2),构图与状态用截图。

**第三个参考就不要了。** 两源已经开始互相牵制,三源变拼贴。

## 2. 从 Linear 的 devtools 读到的真实数字

来源:一次真实 DOM dump(`bVIB3G_row` / `bVIB3G_groupHeader`)。

| 项 | 值 | 备注 |
|---|---|---|
| 行内左/右簇的间隔 | **`gap: 8px`** | 内联写在 `style` 上,是明文 |
| 图标尺寸 | **14 和 16** | 状态字形 14,优先级与头像 16 |
| 状态字形 | **14×14,`stroke-width 1.5`,内圆 `rx=6`** | 一组可直接照抄的数 |
| 头像 | **16×16** | |
| 行结构 | **左簇 + 右簇,标题吃弹性空间** | 行内两个 `ImRUSq_root` 子元素 |
| 标签 | 走 **`--accent` 自定义属性** + 一个圆点子元素 | 与我们的 chip 同思路 |
| 优先级图标 | 带 **`aria-label="Medium Priority"`** | 图标不是装饰,是信息 —— 有名字 |
| 调色板 | 全部 **CSS 自定义属性**(`--color-green` / `--color-yellow` / `--color-text-quaternary` …) | **和我们同一套结构** |

**顺带一个重要结论**:Linear 用的也是"CSS 变量调的调色板",和我们是同构的 —— 所以**它的结构可以搬,值不必搬**。这也说明我们的 token 层方向没错,错的只是缺版式层。

## 3. 从 Zed 拿的一条(对话层)

**对话不是气泡。** Zed 里用户消息和助手回复**都是纯文本**,没有填充、没有边框、没有左右对齐之分;只有**工具调用**被压成安静的单行 mono 条目(`Read crates/gpui/src/element.rs`)。

对我们的意义:我们现在把**最饱和的酸绿**用在用户自己的消息气泡上 —— 而**两个参考都不这么做**。最饱和的颜色应该留给"这是一个动作",不是"这是一句话"。**这一条落地后,`--brand-acid` 的四处用途会重新变得干净。**

## 4. 从 Linear 拿的一条(右栏 / agent 面板)

它的 agent 面板几乎就是我们右栏该有的样子,顺序是:

1. 头部(agent 身份 + 模型名 + `⋯` `✕`);
2. **用户消息 = 一个带边框的圆角盒子**(不是饱和填充);
3. 一行 `ⓘ <id> added to context` —— **上下文以一行小声说明,不占版面**;
4. **`Worked for 10 sec`** —— 可折叠的一行,默认收起(工具干的活藏在里面);
5. 助手散文;
6. **改动块**:`Changed 2 files  +22 -10  👁 Preview` + 分支行(`master ← ride/drv-364-…`),mono,放在一个带边框的容器里;
7. 输入行:`Reply...` + 左下 `Skills ▾` + 右下图标组。

**我们右栏现在只有"空态 + 一段解释文字"。** 这个顺序就是它该长的样子,而且它**天生处理了"运行中"和"跑完了"两个状态** —— 正是我们缺的。

另外 Zed 的 rail 行是**两行式**:标题一行(截断),下面一行小声的元信息(`‹ 分支 · 时间`),有的行还带 **`+23 -2` 的 diff 统计**。这是"列表行信息密度"的直接答案。

## 5. 我们不改的

**中性底、以及"一个饱和色表示一件事"** —— 这些是我们的,不借。

斜切曾经在这张名单上,已经退场:它和边框(切角让 `border` 跟不了斜边)、圆角
(两者抢同一个角)、密集界面(12px 的切量在 36px 的控件上占三分之一高度)三者
都打架,而我们没有可以对标它的参照物。下一件事就是给它换一个**有文档、有
角色表、有对比度保证**的外部调色板底座(见计划)。
参考只用来定**版式与层级**,不用来定**我们是谁**。

## 6. 按参考看,我们现在的三处偏离

| 我们的现状 | 两个参考 | 判断 |
|---|---|---|
| 用户消息 = 酸绿填充气泡 | 两边都是纯文本 | **偏离**。最饱和的元素用在了最不该饱和的地方 |
| 输入行 = 大酸绿 `Send` 按钮 | 两边都是"小图标发送 + 右下角 mode/model 下拉" | 偏离。同屏两个酸绿 CTA 互相抵消 |
| 左栏 ~90px 细条 | Linear ~205px · Zed ~200px | 偏离。装不下"图标 + 标签 + 两行元信息",所以看着空且难懂 |

前两条互为因果:因为气泡抢了酸绿,输入行的酸绿就不再是"唯一的主操作"。

## 7. 还缺的参考状态

现在手上都是**内容饱满**的屏。我们真实的毛病出在状态上,所以还缺三张:

- **列表为空**的时候(对应我们"空会话一片空白");
- **窗口很窄**的时候(对应我们右栏标签条溢出、文字被挤);
- **深色**方案(我们两边都要对等)。
